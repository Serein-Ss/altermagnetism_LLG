## 📋 分类规则

Markdown 报告统一进入 docs，报告对应的图表和机器可读分析结果进入 assets。
GUIDE 是唯一保留在 docs 之外的计划目录；根目录仅保留 README.md 这一份 Markdown。
requirements.txt、pytest.ini 和 Git 隐藏配置是工具入口，不作为散落文档移动。
文献 PDF 附件进入 docs/attachments/data/literature_reproduction；参考图片进入 assets。
模拟状态 checkpoint 属于 data；学习模型权重属于 output。

## ⚙️ 配置和代码

conf/literature_reproduction 保存文献物理参数和批次配置。
conf/research 下 models、experiments、datasets、runs 分别保存模型、实验、数据集和运行配置。
conf/archive 保存旧冻结批次与从代码快照中分离的配置；旧批次横跨多个研究阶段，保留批次结构便于溯源。
scripts/core、literature、generation、datasets、model、training、inference、analysis、visualization、validation、tests、workflow、config 分别保留其代码职责。
scripts/archive 中的物理 Python 内核未修改；快照中的计划文档、参数、提交脚本已分离保存。
旧批次清单保留旧路径作为历史事实，可通过 scripts/core/project_paths.py 的 resolve_recorded_path 查询迁移位置。
新批次使用更新后的路径；旧冻结编排脚本不能直接重放，必须采用续跑适配入口。
